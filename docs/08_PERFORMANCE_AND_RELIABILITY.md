# 08｜性能、资源和可靠性合同

以下全部为**待实现/待实测的开发默认值与验收目标**，不是在用户电脑上测得的结果。不得在发布说明中去掉此前提。

## 1. 有界调度

P0 当前选中原图/当前文本页/用户播放；P1 当前可见缩略图与新条件所需字段；P2 相邻Fit预取；P3 未显示区域元数据；P4 分配大小补齐、缓存清理与周期核对。

每类任务去重键含fileVersion+representation；共享进行中任务采用引用计数，取消一个订阅者不误杀仍被当前预览依赖的任务。背景队列满时合并/丢弃可重建预取，不能丢扫描事实后假称完成。

初始队列：扫描批次最多8×512条；元数据候选最多2048项；缩略图最多1024项（保留可见项）；图像重解码最多前台1+后台2；视频封面1；DB读并发≤4、写1。UI批次50ms或64项，单批UI工作预算≤4ms，不能一口气追加几万控件。

CPU预算：原生库线程总配额起点min(16,max(2,logicalProcessorCount/2))，前台优先得到至少4线程（机器不足则使用可用预算），剩余分给后台。不是每个worker各自使用全部核。libvips默认按核并行，需要显式设定线程限额。[S11]

存储：本地SSD初始后台读取并发4、HDD/未知介质1、SMB每共享1（可实测调到2）。同一物理盘上的多个任务共用预算；不要仅按根目录数独立放大并发。配置界面可选“自动/保守/高性能”，默认自动，不向用户堆几十个线程滑块。

## 2. 内存与磁盘默认预算

| 资源 | 64GB参考机器默认 | 行为 |
|---|---:|---|
| 应用进程树CPU内存软预算 | 6GiB | 包括原生worker、共享内存、WebView、页缓存；合计核算尽量避免共享页双算 |
| 应用进程树保护阈值 | 8GiB或可用内存安全线先到 | 停后台、回收、限制新任务；不因清缓存清掉当前原图 |
| GPU可淘汰纹理 | 1GiB软预算 | 当前视区固定，小边界LRU；不得缓存整个目录原图 |
| Thumbnail磁盘缓存 | 10GiB | LRU，256/512/1024分级，不能全部生成三份 |
| 大图/RAW临时tile和中间缓存 | 8GiB | 单任务预约，失败/崩溃后安全清理 |
| 结果会话数据库 | 1GiB | 活动1+历史最多2；额外空间不足明确错误 |
| 文本子系统增量内存 | 192MiB | 字节/字符/布局/稀疏索引总计 |
| 动画帧缓存 | 256MiB软预算 | 合成状态+少量帧，超过用受控降级/磁盘 |
| 缓存盘空闲底线 | max(5GiB,磁盘容量2%)，上限20GiB | 先计算可用预算，不能填满系统盘 |

低资源机器预算按物理内存12.5%起点、上限6GiB，保护线不超过物理内存25%，同时尊重系统当前可用内存。GPU预算按真实adapter/DXGI预算动态降级，不默认一定能用4090。i9-14900KF不依赖核显进行解码。

61MP展开RGBA8约244MB，16位和中间缓冲会更多；预算必须按解码后而非压缩文件长度估计。宽×高×通道×字节必须checked。单个图像源默认自动解码上限300MP、最大边1,000,000px；超限可在受控查看路径提示并申请临时空间，但不能绕过进程保护；正常61MP不能被拒绝。

显示当前图片所需预算不足时提示受限预览，仍可导航；该状态不能被写成FullReady或用作原图功能的验收通过。

## 3. 取消、超时和故障

UI取消/切换反馈P95≤100ms；原生重解码合作取消宽限250ms，仍占用则终止对应worker，目标1秒内可给新前台任务腾出worker。文件I/O在内核不可立即取消时不承诺线程消失，靠进程隔离，并把终止失败作为诊断事件。

本地普通图片任务软超时10秒、RAW/大图30秒、硬上限60秒；用户仍停留且显示真实阶段进度时可延长一次，不能形成无期限重试。背景缩略图10秒，视频封面15秒，FFprobe10秒，MD解析3秒；SMB读取超时20秒后显式重试。

worker单请求最多重试一次；同一文件同一版本连续3次崩溃加入本会话隔离清单，提供手动重试。引擎启动整体失败触发组件诊断，不能把全库每个文件标坏图。主进程异常不清用户数据；下次启动回收有owner标记且无活跃租约的临时目录。

磁盘满、缓存不可写：禁后台缓存、可用内存预览继续，给出清理入口。数据库写失败/损坏：保护现有文件，备份和恢复说明，不自动抹除。睡眠恢复重验文件/设备/时间，不继续把过期GPU纹理用于新设备。

## 4. 参考基准与门槛

标准性能机：用户同档CPU/GPU/64GB、Windows11、Release x64、本地NVMe、常规杀毒开启；记录OS版本、驱动、显示DPI和刷新率、电源模式、磁盘型号。不能拿网络根的耗时和本地NVMe混为一个数字。

| 场景 | P95目标 | 约束 |
|---|---:|---|
| 已启动、已索引、首屏缩略图热缓存 | ≤300ms | 不是含exe进程启动的冷启动 |
| 应用冷启动到可操作外壳 | ≤2秒 | 无目录全扫阻塞；WebView2不在启动时创建 |
| 常用有索引筛选到首批256项 | ≤300ms | 十万文件；任意包含搜索单列报告 |
| 百万已索引元数据简单筛选首批 | ≤500ms | 实际catalog，不是内存数组 |
| Ready会话跳到第80万项读一页 | ≤200ms | 不用深OFFSET、UI不常驻全量 |
| 100万项固定结果快照Ready | ≤15秒目标、≤30秒硬门禁 | 期间UI可操作、可取消、WAL有界 |
| 相邻Fit已预取后的图像切换 | ≤100ms | 记录实际Presented，不只记录事件触发 |
| 常规≤24MP JPEG冷Fit | ≤500ms | 解码/上传完整路径 |
| 61MP ARW内嵌预览 | ≤800ms | NVMe真实样本；不能与RAW完整解码混算 |
| 61MP ARW原分辨率可见区 | ≤4秒目标，≤8秒硬门禁 | 真实LibRaw开发路径，须解释冷/热 |
| 本地1GiB/5GiB文本首屏 | ≤500/800ms | 不等待全量行索引 |
| 取消/切换UI反馈 | ≤100ms | CPU/网络后台忙时也测 |
| 60Hz滚动/平移 | 帧时P95≤20ms，P99≤50ms | 不能只报平均FPS；反复>200ms卡顿阻断 |

原图/大目录性能目标受真实格式影响，必须逐场景给出PASS/FAIL，允许通过优化达标；不能用一次快速样本替代所有样本，也不能把目标改成“尽量快”。不同硬件的数据单独记录，不伪装参考机验收。

## 5. 测量方法

冷/热定义：冷指应用自有缓存清理或关闭新开（分别注明），OS缓存未清也要注明；严禁未说明把OS热缓存叫磁盘冷读。热预取必须证明前一个任务确实完成。每个常用交互场景至少100次采样，报告P50/P95/P99/max和样本量；昂贵RAW至少30次，单列样本数不假装100次。

时间点：Input/QuerySubmitted/FirstRowsCommitted/FirstVisiblePresented/FullPixelsPresented；同时记录排队与解码耗时，不能把队列等待从“打开速度”中去掉。帧时间使用实际渲染present证据/ETW或经过验证的内部时钟；诊断CLI纯算法耗时不能替代UI呈现。

长稳测试：10,000次切图、30分钟滚动筛选/MD/音频切换、睡眠恢复和网络断开；停止活动后10秒内可淘汰内存应回到预算附近，峰值不持续阶梯增长。统计CPU private bytes、GPU committed、句柄、线程、worker数、缓存磁盘和数据库WAL，包含WebView子进程。

## 6. 发布阻断级别

RELEASE-BLOCKER：源文件被写/删除、越权读取执行、错误图片覆盖、离线误删索引、数据统计实质错误、核心格式/原图伪装、主进程崩溃、UI持续冻结/泄漏、不可启动安装包。
MAJOR：核心流程明显不完整、主要性能硬门禁失败、重要操作不可键盘访问、恢复错误；一期发布前必须修复。
NON-BLOCKING：不影响核心的展示小瑕疵/非承诺格式；记录复现和后续版本，不隐藏。
