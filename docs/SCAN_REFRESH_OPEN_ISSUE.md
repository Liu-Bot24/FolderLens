# 大目录扫描期间反复刷新（未解决）

状态：2026-09-13 用户再次报告，原因未确认；暂停本地测试和进一步排查，交由 Pro 整批审计。

## 已知现象

- Windows 11；选择含多层子目录的大目录，图片分类，未开启文件夹分组。
- 用户不主动刷新，仍看到频繁刷新；已经显示的缩略图再次出现大片空占位。
- 最近截图状态为“首批 256 项 · 正在固定完整浏览顺序…”，扫描已发现约 26.4 万文件、862 个目录。
- 此前同类问题也出现在分组视图，不能仅根据是否分组缩小为唯一根因。
- 最新程序更新后只启动一次，之后没有自动化点击、切换目录或刷新用户窗口；隔离测试进程当时已结束。用户随后关闭程序。

## 已观察的代码线索（不是根因结论）

- `MainWindow.xaml.cs` 的扫描进度回调经 `ScanPreviewRefresh.TryBegin` 发起 `RefreshQuery(scanPreview:true)`；扫描结束和元数据填充结束也能触发查询。
- `RefreshQuery` 在结果句柄为空且未分组时构建首批数组并 `AttachBrowserView(initial)`，之后等待完整快照。已有结果时有快照差分、缓存行复用和增量通知逻辑。
- `CatalogStore.BuildSnapshot` 涉及读取事务、排序、会话写入、取消、WAL/会话容量和期限约束。当前没有证据确认是哪一种路径导致了用户现象。
- 真实目录规模远大于多数确定性原生夹具；首批缩略图测试仅验证完整快照完成前缩略图可以排队，不验证首批阶段的重复进入与长时间稳定性。
