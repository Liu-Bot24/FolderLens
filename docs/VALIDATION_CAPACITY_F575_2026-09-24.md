# FolderLens 目录容量与 F575 复审修复验证（2026-09-24）

## 结论与范围

基线为已推送 `57540dae414d41d9c81a656d47067263064d4037`。原 Pro 会话「GitHub代码审计」对此固定提交指出 F575-01、F575-02 两项 P2 队列竞态和 F575-03 一项 P3 操作结果提示问题；F094-03 当前无可达普通桌面升级路径，不作为本次必修。本轮没有重新发送审计请求。

目录容量的根因与队列竞态不同：旧窗口仅汇总浏览 SQLite 索引；该索引的 2 GiB 固定写入上限会使仍在前台浏览的目录扫描停止，因此容量不能获得完整值。导航时停止旧范围本已有独立任务退休路径，容量入口却额外要求主浏览索引尽量扫描整根。现改为独立元数据遍历，逐步显示下界，只有确实遍历结束且无不可读目录才标记完成；正式运行的浏览库取消固定 2 GiB 上限，保留本机剩余磁盘空间保护。

## 不能据此宣称的事项

精确容量仍须枚举目录元数据；10 秒是当前本机这个目录的实测，不保证其他盘、SMB、云盘或持续变化的目录同速。当前测试会话看不到 U/Y/Z 映射盘，因此独立容量在真实 SMB 上仍为 NOT_RUN；网络及可移动路径继续交给隔离 ScanWorker。真实前台 Explorer 拖出与最终选中、云提供方、安装器、多屏 DPI、A054a 长稳与一期完整发布验收未因本轮转为 PASS；干净 Windows 与低内存验收保持用户决定的 SKIP。

最初离屏红测在普通沙盒会话尚未进入业务测试即因 Windows `SetShownInSwitchers` 失败；在获准的隔离离屏会话中改正测试夹具后，最终原生回归如上通过。不能把启动失败当作业务红测通过。
