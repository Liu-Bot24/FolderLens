# 目录容量分层排名与窗口简化验证（2026-09-24）

## 问题与修复

旧“所有子文件夹排名”把每个后代目录的**整棵子树**都列进同一榜单。固定夹具中的 A=50、A/AA=30 会同时出现，榜单合计 120，而当前目录真实文件大小只有 100。新的按深度排名在每条分支只保留一个目录：一级 A50、B40；二级 A/AA30、B40；三级超过实际层数，仍显示各分支的最深目录。榜单只列文件夹；右侧分布另列上层直属文件，合计仍为 100。

容量窗口现在只统计当前文件夹；移除“占用空间”切换、第二张分配大小卡片和“打开窗口时的筛选结果”入口。改变排名层级只重排内存中的目录聚合，不重启文件系统遍历；刷新才重新枚举。底层快照/分配元数据接口仍保留，供其他已有功能使用。

## 验证结果

- 红测试：`CapacityTests` 新增深度排名断言后，旧源码因缺少 `RankAtDepth` 无法编译；修复后同一筛选测试 6/6 通过。正例覆盖一级、二级、超过实际深度以及右侧分布的直属文件余量；反例检查父目录 A 不与子目录 A/AA 同榜出现。
- `dotnet test` Release 全部 624/624 通过，TRX：`artifacts/capacity-depth-20260924/unit/capacity-depth-20260924.trx`。
- App Release 构建 0 错误。NU1900 仅表示此环境无法访问 NuGet 漏洞数据服务，不等于已完成依赖安全审计。
- 离屏原生 `capacity-ui`、`physical-capacity` 最终都为 PASS，报告与截图在 `artifacts/capacity-depth-20260924/native-final/`。验证了两张指标卡、不同窗口宽度、下钻和返回、二级无父子重复、三级浅分支回退、切层级不重扫、刷新读取新增文件、主窗口换根后旧容量窗口退休。
- 沙箱内第一次 WinUI 测试启动因 WinRT `IsShownInSwitchers` 不可用而失败，未进入测试；在正常桌面令牌下离屏运行后可启动。一次中间测试失败是旧夹具仍断言已删除的快照选项，更新为新口径后最终通过。测试的成功报告不带 `error` 字段，首次汇总脚本因此异常；最终报告与进程退出码独立复核均为 PASS。
