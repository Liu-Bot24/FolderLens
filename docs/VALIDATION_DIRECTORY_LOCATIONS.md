# 收藏位置与旧选择修复

`2cc8b1a` 审计确认四个问题：重叠索引的旧选择可以重新加入已失效收藏；改名后的新根可能继承旧归属；完整扫描没有清理已消失的 excluded 子树；刷新保留视觉对象时仍携带旧路径修订。

## 修复

- 收藏主键变为 `(collection_id, directory_location_id, location_key)`，v5 文件摘要保持不变。持久化目录位置与绑定区分实际位置及存在代次。扫描开始的同一属性句柄提供目录身份和解析路径；证明同位后才合并收藏，未知时保留各自归属。
- 新目录在首批文件发布前已有隔离绑定。新根及深层目录不能仅凭物理 ID 继承旧标签。确认旧位置失效时只清除旧实例；确认合法同位时合并全部收藏夹归属。实例退休后不复活。
- 根变更核对位于数据库事务外，事务内重验根 epoch、路径修订及绑定修订。旧命名空间无法确认时保留原收藏；祖先目录确认消失与访问路由失效分别处理。候选数量超过有界核对范围时继续隔离扫描。
- 所有收藏消费者匹配完整二元组，包括包含/排除、虚拟收藏根、属性/星标、来源目录、元数据补全和稀疏批量操作。批量临时表按二元组去重，继续使用选择区间索引。
- sessions v5 保存位置与绑定修订。普通、快捷和批量收藏在事务中拒绝过期观察。新快照更新 FileRow 的权威观察，同时保留行、位图、容器和 ItemsSource；比较共享区间时纳入路径与绑定观察。
- 只有父目录完整扫描后，才将确实消失的非 missing 子树清理；仍存在但 excluded 的目录保留收藏。

catalog v7 迁移先备份，再依据每条旧成员的 entry_id 锚点转换，不把旧标签扩散到同物理摘要的其他位置，也不重写 Files.location_key。取消回滚整个迁移；旧版本拒绝较新 schema，回退须使用备份。
