# 分组标题滚动修复验证

## 问题与改动

缩略图模式连续跨越多个小分组并反向滚动时，分组标题可能出现在文件卡片内部。长、短标题均可触发，停止后台更新后仍可复现。

缩略图列表的 `ItemsWrapGrid.AreStickyGroupHeadersEnabled` 设为 `False`，让标题与所属分组一起滚动。标题不再固定在列表顶部，这是预期的行为变化。继续使用原有虚拟化布局、标题模板和集合；详情视图不变，无新增依赖或设置迁移。

## 验证方法

`--verify-refresh --verify-group-header-layout --verify-wide` 使用独立数据目录和合成图片，在离屏 WinUI 窗口中检查 24 个大小不同的分组。覆盖 100、160、240、300 档缩略图、连续及反向滚动、后台分组更新。标题和卡片统一以 ItemsPanelRoot 为坐标系，检查列表中部的相交；无有效可见标题或发生重叠时测试失败。

`--verify-legacy-sticky` 仅用于重新启用旧行为的负对照，普通测试不覆盖生产 XAML 配置。可用 `--verify-native --verify-dark` 检查原生深色主题，`--verify-short-titles` 检查短标题，`--verify-large-groups` 检查较大分组。

## 已验证结果

- 修复前，同一回归测试失败，捕获标题落入卡片内部。
- 修复后，圆角主题宽屏完整场景通过：743 帧、2,964 次可见标题观察，无中部重叠。
- 原生深色主题窄窗口、短标题完整场景通过：2,220 帧、677 次可见标题观察，无中部重叠。
- 分组折叠/展开、跨视图选择、多选、折叠期间增删相邻组通过。
- 后台分组换序保留可见卡片、缩略图和滚动位置，通过。
- 十万条结果的折叠/展开保持按需加载；展开仅创建 256 个可见页内对象。分组惰性加载检查通过。
- Release 构建通过；NuGet 漏洞信息源不可达警告仍存在，不代表依赖安全审计通过。

上述为本机真实控件的离屏验证，不代表所有设备、DPI、输入设备或项目其他问题已经验收。未据此宣称资源管理器“打开文件位置”异常或长期内存增长已经修复。
