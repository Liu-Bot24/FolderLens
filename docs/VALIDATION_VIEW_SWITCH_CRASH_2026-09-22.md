# 扫描期间切换视图崩溃回归

## 故障与修复

扫描持续更新分组时，在缩略图和详情之间切换可能导致进程以 `0xc0000005` 退出。现场 Windows 事件与原生复现均经过 `BrowserVector.Changed`、`BrowserCollectionView.OnGroupsChanged` 和 WinRT `VectorChangedEventHandler.NativeDelegateWrapper.Invoke`。

切换前后复用同一个分组 `ICollectionView` 通知投影，会将新分组通知继续交给该投影保留的原生控件回调。现在切换时解除两侧控件绑定、停止旧投影订阅，再为目标控件创建新的通知投影。原有分组模型、折叠状态、虚拟文件结果及行对象保持；不吞异常，不暂停扫描，不改为全量加载文件。

创建投影的成本随分组数增长，读取的是各组数量，不遍历全部文件。原生控件内部的具体失效指针尚未通过转储定位；结论依据同故障堆栈的可重复复现和单变量对照。

## 对照证据

基线：`ffbedc1a0fbcd967d8adc8b6ea1bd95e757e447d`。

| 场景 | 结果 |
| --- | --- |
| 原实现：实际切换控件后发布分组移除/插入 | 第一次切换后即发生 `0xc0000005` |
| 原实现：同样更新分组，取消视图切换 | 10 次发布通过 |
| 原实现：保留切换，取消测试主动 GC | 仍在第一次切换后崩溃 |
| 仅调整两控件绑定先后顺序 | 仍崩溃；该试探改动已撤销 |
| 独立通知投影：连续切换并更新分组 | 100 次切换、100 次发布通过 |
| 实际扫描 12,000 个合成图片文件 | 197 次切换，其中 175 次发生在扫描中；4 次结果发布，最终文件及分组数量正确 |

原生回归入口：

```powershell
FolderLens.App.exe --verify-refresh --verify-switching-group-updates --data-dir <独立证据目录>
FolderLens.App.exe --verify-refresh --verify-switching-live-scan --data-dir <另一个独立证据目录>
```

每次使用新证据目录。测试运行实际 WinUI 控件，在屏幕外创建窗口，通过 Toggle 自动化接口调用视图按钮，不操作前台鼠标或键盘。
