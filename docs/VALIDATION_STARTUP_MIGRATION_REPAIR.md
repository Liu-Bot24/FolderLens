# 启动升级、目录别名与收藏徽标修复

旧索引 v4 升级会先复制整个数据库，再重写文件键；接续到 v7 又复制一次。大索引在启动阶段因此长期不可用。现在各版本迁移不再自动生成全库副本，v4/v5 直接在一个事务内进入 v7，不提交中间 v6。迁移期间使用 FULL 同步，退出后恢复连接原设置。

v4 文件键按 rowid 游标每批 4096 条转换，索引只重建一次，进度报告实际处理数量。各批仍属于同一事务；取消后回滚，不是断点续跑。成员按原始 entry_id 的目录锚点直接转换到最终复合键，避免中间按物理摘要合并不同位置。已有恢复备份不自动删除；成功提交后不能直接用旧程序降级。事务日志仍需要临时磁盘空间。

同时修复固定提交 3b7c04a 审计的两项问题：

- 访问联接删除或改指向时，先比较新路径与已保存的解析位置，再验证旧解析位置本身；访问路线不可用不能单独证明原位置消失。提交重验解析锚点、根与绑定修订。真实目录改名及离线保护保留。
- 星标查询以收藏相关观察值比较代替单纯对象引用比较。仅重排时可以应用结果；观察变化时合并补读，每批最多 256 项，不逐行创建任务。
