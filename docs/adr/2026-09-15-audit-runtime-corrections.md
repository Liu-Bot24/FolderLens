# 审计修正：增量列表、资源监控和临时库到限

## 证据与范围

对 6a263c6 的 DSH 源码审计进行逐项核对。新增回归首次运行 7 项中 3 项失败：普通列表选中阻止增量发布；工作进程注册同步执行资源采样；缩小至 2 MiB 的测试库在真实扫描写入链路抛出 SQLITE_FULL。

## 决策

- 普通列表中选中文件不再锁定增量发布。窗口预览、全屏和幻灯片仍保持序列稳定。增量替换保留当前选中对象，按发布时的最新选择恢复；不因恢复选择把视口拉回该文件。该规则细化了浏览序列稳定要求：列表可增长，专用预览期间固定顺序。
- 工作进程启停仅更新注册集合，资源采样由一秒定时器负责。使用 GetProcessMemoryInfo 查询私有提交量，避免每个进程重复执行 Process.Refresh。仍统计工作进程树及 WebView，仍保留内核 Job 上限；没有按窗口焦点暂停后台任务。
- 新进程加入共享 Job 时不再将已扣除宿主占用的限制重设为全额硬顶。首次尚无测量时使用半额保守值；不完整测量只能收紧上限。
- 临时主库硬上限不增加。写入扫描批次前检查剩余空间并预留收尾余量；达到预算或遇到 SQLITE_FULL 时结束为部分扫描，保留已提交记录，不按缺失删除未扫描项。其余扫描和元数据任务停止增加该库内容。界面明确说明扫描已停止、已有结果可浏览及重新打开较小范围的处理方式。
- 到限处理不是无限规模支持：本轮未实现分段索引或不重启回收旧根。真实磁盘完全写满可能连错误收尾也无法写入，原异常仍会进入错误处理，不声称成功。

## 未照搬的审计建议

- 枚举已有最多 128 项/约 50 ms 的批次和工作进程 20 秒 I/O 超时；单个阻塞 I/O 仍可等到超时，未证明需要拆开写库名额或允许同根并发。Reconcile 本身在完整扫描未结束时返回，报告中的同根同时核对并非该入口的实际行为。
- 300 ms 文件稳定观察时间由批次共享；幻灯片循环已经跳过非图片。不按误报删除文件真实性检查。
- 不扩大缩略图缓存、不预热 WebView、不恢复跨启动目录历史，也不以旧缓存替代源文件确认。离线收藏时延、网络预取检查、结果快照空间等建议仍需各自证据，不列为已修复。

## 验证

- 原 3 项失败用例转为通过；定向资源/扫描测试 24 PASS。
- 全量 402 PASS，0 失败、0 跳过，约 23 秒；记录 `artifacts/tests/dsh-audit/dsh-audit-full.trx`。
- Release 编译 0 错误，7 项既有 NU1900（无法访问 NuGet 漏洞服务）。
- 30 次私有内存查询微测量：Process.Refresh 111.49 ms，新查询 0.13 ms。这只证明采样路径开销下降，不代表视频帧率或整机性能增益。
- 原生 `--verify-first-audit-selected` 场景覆盖缩略图/详情、新文件发布、选择/视口保持、幻灯片固定序列；本轮未启动前台窗口，NOT_RUN。策略测试及编译不替代 WinUI 原生验收。

API 依据：[GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)、[PROCESS_MEMORY_COUNTERS_EX](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)。
