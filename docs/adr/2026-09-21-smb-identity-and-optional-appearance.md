# SMB 文件标识兼容与可选外观

## 背景

部分 SMB 服务端不支持 `FileIdInfo` 的 128 位标识查询，但支持 `GetFileInformationByHandle` 返回的 64 位文件索引。原扫描边界校验将前者不可用视作身份丢失，导致具备读取权限的目录在首次枚举前被拒绝。

## 决策

- 优先使用现有 128 位身份；不可用时，在同一个已打开句柄上读取旧式文件信息。要求文件索引非零、创建时间有效且与基本信息一致，否则仍返回未知身份。
- 旧式身份使用独立 `legacy:` 命名空间，包含卷序列号、文件索引和创建时间。目录枚举不能把扩展条目的 128 位 ID 拼接到旧式卷标识上。保留扫描前、批次间和结束时的目录替换检查。
- 外观通过独立 XAML 资源字典定义。默认“原生”保留原有颜色和布局；“柔和”使用蓝灰背景、圆角面板和淡紫色范围提示。保留系统原生控件模板、输入行为与虚拟化。
- 外观选择独立持久化，并在运行时替换资源。切换不重建浏览视图，不提交查询，不修改系统主题。两个资源字典均保留系统高对比度颜色。

## 验证边界

实际 SMB 映射路径、UNC 路径和第二个 SMB 盘均通过直接枚举与独立扫描工作进程读取。对应失败基线、修复结果、单元测试和原生离屏测试见本轮验证记录。高对比度及前台人工操作未执行，不能将自动测试视作完整实机验收。
