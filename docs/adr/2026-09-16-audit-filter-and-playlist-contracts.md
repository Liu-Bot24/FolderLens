# 筛选终态与收藏身份补齐

审计 eedcf96 的最小反例：已完成媒体探测但时长为 NULL 的文件一直 Pending；收藏目录身份由未知补齐后，同一运行成员留下两条持久映射，取消收藏仅删除其中一条。

查询以同一文件版本的字段组终态判断缺值。ready 缺值为 Unresolvable；FFprobe 明确没有音轨时，media 组保留 ready 并记录 NoAudioStream，音频编码条件为 NoMatch。探测尚未完成仍为 Pending，NULL 仍为未知。筛选 v1 的 includePending 保持既有“仅待判断”语义，界面、状态文字和 schema 说明一致。

基本筛选先完整校验，再取消查询、导航或启动扫描；非法草稿保留已接受视图。基本控件负责大小区间和宽高下限，清空下限保留高级上限。有效草稿条件随目录导航保留，关闭时仍保存已生效筛选。

目录位置的身份补齐只迁移当前有效位置实例明确拥有的持久收藏，在同一写事务中按旧元组匹配、插入新元组并去重。身份或位置确定改变仍退役旧实例，不按文本路径恢复收藏。旧版无连续身份证据的映射保留，用户可分页查看未恢复记录、移除记录，或明确确认重新收藏当前位置的文件；重新收藏不是自动确认旧文件连续存在。

大批量行变化的阈值统一放在 VirtualRangeCollection.UpdateRanges。超过 4096 个增删项切换虚拟索引并发一次 Reset，调用方继续按身份保留可见行和解码位图，恢复选择及视口。小批量仍逐项通知以适配 WinUI。

发布及原入口更新必须在本次交付的新目录重新构建原生库。构建失败或目录已存在即拒绝，不能复用上次 Release DLL。托管和原生编译前后仍核对同一源输入指纹。
