# 大范围文件夹重排采用一次有界重置

状态：采用。范围：已有分组的顺序发生大量变化时的原生列表发布。

五万组逆序的实际原生验证连续测得 181.9 和 186.8ms。虽然位置计算使用了树状数组，ObservableCollection 的逐项 RemoveAt/Insert 仍需反复搬移底层数组；绑定后的分组投影还会反复计算偏移。

当组位置差异超过 4096 时，先解除旧投影订阅，按新顺序一次构造集合，再向同一个 BrowserCollectionView 发布 Reset。复用仍存在的 BrowserFileGroup 对象，因此折叠状态不丢失；当前文件、行身份和视口继续由既有的发布保留逻辑处理。小范围变化保持原来的逐项通知。

这延续了文件范围增删超过 4096 时的一次 Reset 策略，不保证大范围重排仍保留每一个控件容器。不得通过保留已过时的组顺序来规避重排成本。

验证包含五万组真实更新耗时及身份顺序检查、当前项和总数在通知期间的一致性、旧集合订阅解除、小范围容器保留和大范围重置。完整绑定、布局、物理滚动的性能仍需独立测量，不把纯组更新计时等同屏幕呈现。
