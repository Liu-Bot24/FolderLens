# 可绘制预取与同目标任务接管

状态：已实现，验证记录见本批审计文档；完整性能验收仍以实际测量为准。

## 问题与证据

原预取保存 PNG 字节。即使命中，选择新图仍需异步创建 CanvasBitmap。
同一批大 JPEG、相同侧栏预览的首次目标 Draw 测量中，后四次充分预取切换为
56–121 ms；只增加预制位图后为 4.5–7.5 ms。首次文件状态探测进程启动另有
约 323 ms，不能归因于 PNG 解码。
最初测量没有成功进入大图查看模式；上述数字不作为大窗口性能验收。

选择下一张原先无条件取消旧预取；原生屏障反例显示同目标再次执行前台
worker fit。滚轮还存在独立错误：扣除多个刻度，却只导航一张。

## 选择

- 继续使用既有隔离解码工作进程和受控 PNG 资产，不改变 IPC 格式。
- 当前图加载工作进程自有 PNG 时，使用显式关闭的原生 FileRandomAccessStream，
  避免托管流适配。路径重载虽然更快，但实际复验发现加载后保留文件锁，导致
  ReleaseAsset 删除失败、目标图片无法显示；关闭加载操作也不能消除锁。
  显式关闭原生流后，位图有效且资产立即可删除。相同资产交替各 100 次，
  原生流 P50 18.9/P95 22.1 ms，托管流 P50 83.4/P95 113.3 ms。
  完整冷切 111 次已通过，P50 309.7/P95 493.9/max 540.1 ms；
  旧托管流基线为 408.1/635.5/908.1 ms。用户可能同时使用电脑，非受控参考机验收。
- 两张预取图片可额外持有已解码 CanvasBitmap，按像素计费，上限 64 MiB；
  原 PNG 缓存仍独立限制在 32 MiB，细节缓存维持既有预算。
- 命中时将位图所有权交给当前显示，缓存不再拥有该对象。淘汰、内存压力、
  换根、关闭和设备重建释放仍由缓存拥有的位图。设备代次不匹配时重新创建。
- 选择仍核验源长度、修改时间、索引版本、根 epoch、在线文件授权；后台预热
  文件状态探测不替代选择时的核验。
- 对根、结果代次和目标行匹配、已解码但显示准备尚未完成的预取允许接管，最多等待 200 ms。
  超时取消旧预取并走正常前台路径；不同目标仍取消旧任务。没有固定输入防抖。
  实验否定了等待任意在途解码的做法：后台低优先级解码未结束时等待，会让快速连续
  切换额外延迟约 200 ms。因此仍在解码或启动阶段的任务取消后由前台处理。
- 按最近导航方向先预取相邻图片，再处理另一侧，邻图适屏仍先于中心细节预热。
- 一个滚轮事件携带多个刻度时一次定位最终目标；不足一个刻度保留余量，
  不丢导航距离，不要求中间每张都完成解码。

## 成熟实现参考与边界

参考 JPEGView 的已解码对象、方向性预取与显式所有权，以及 qView 的已解码
缓存和在途接管；没有引入其 UI 框架或复制完整任务系统：

- [JPEGView 固定版本 JPEGProvider.cpp](https://github.com/sylikc/jpegview/blob/a4cf718710711c2678190fca2381f01358cebcf6/src/JPEGView/JPEGProvider.cpp)
- [qView 7.1 固定版本 qvimagecore.cpp](https://github.com/jurplel/qView/blob/0ec246b78c310d5c842836a91566db24037c75c2/src/qvimagecore.cpp)

没有公开证据能确认 FastStone 采用相同缓存层、预取数量或 GPU 策略。
旧的不同尺寸图片观察不能构成两产品的定量性能结论。

后续真正进入大图的 111 次测量，等待预取后的 104 次 P95 8.6 ms，其中一次
未命中，最大 375.2 ms；PNG-only 对照 P95 150.6 ms。对照期间一次发布文件
核对与测量重叠，因此差异支持缓存方向，约 94% 是该组局部观察值，不是严谨
对照下的产品整体提速比例。最终验收须同版本、无并发基准地复测。

冷路径中仅改变 PNG 无损编码参数的实验，没有端到端收益，已经撤销生产调用。
直接 BGRA 在独立位图加载中更快，但仍须扩展 IPC、尺寸校验与各消费路径；
优先采用同一 PNG 的显式原生文件流，变更范围更小。依据的是本机对照和
[Win2D 位图 API](https://microsoft.github.io/Win2D/WinUI3/html/Methods_T_Microsoft_Graphics_Canvas_CanvasBitmap.htm)，不是推断 FastStone 的内部实现。

预制缓存改善热路径，不等于所有冷图达到同等延迟。CanvasControl.Draw 是
应用提交绘制的终点，不等于显示器 Present。小夹具、设备替换恢复不能替代
大规模长稳、混合 DPI、真实驱动丢失和总显存验收。
