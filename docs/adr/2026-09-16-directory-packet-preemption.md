# Directory packet scheduling and Markdown navigation readiness

Changing the displayed subtree previously changed only the next directory chosen by the scanner. An already running large directory still had to finish. A mapped-drive native run published the requested scope promptly but left it empty for about 33 seconds. A reduced 1,025-file regression reproduced the same scheduling fault: after requesting the small sibling, all 897 remaining old-directory files arrived before its first file.

Traversal now selects work between packets of at most 128 entries. Up to eight directory enumeration positions remain open; the rest of the traversal queue and branch fairness history stay in SQLite. Three turns prefer the displayed subtree and every fourth turn compares suspended and unopened branches fairly. Paused enumeration positions resume without rescanning committed entries. Reconciliation still requires a terminal completed packet; cancellation and failures preserve incomplete observations.

Scan protocol v5 adds request-driven cursor packets. The existing single enumeration worker owns at most eight cursors and advances only the requested one. There is no additional worker process or unbounded producer queue. The existing identity-probe worker, per-packet timeout, process job limit and global two-packet admission remain in force. Transport failure retires all affected cursors and fails the scan rather than claiming completion. A target outside eight occupied contexts waits for capacity; this bounded design does not promise immediate access under arbitrary storage stalls.

The first implementation regressed two existing branch-fairness tests. Fair admission now compares active and queued branches using the same turn history; the original assertions pass unchanged. Tests also cover cursor interleaving without duplicates, one-process ownership, cancellation and the cursor admission limit.

A separate native Markdown failure identified a navigation race. The visibility timer assigned image sources before document navigation completed, causing slow image decoding to hold the navigation completion event until its deadline. Viewport loading now stays stopped while the document is navigating and begins after navigation completes. The navigation deadline and document security settings are unchanged.

Validation: 511 unit/integration tests passed with no skips. A mapped-drive native run performed 16 scope switches while scanning: scope publication took 65–144 ms, first discovery took approximately 1.84–2.18 seconds, and the maximum UI heartbeat gap was 118 ms. These are bounded samples, not the full performance acceptance matrix or a complete network-root scan. Native comprehensive navigation, rejected-admission monitoring, long-text EOF, image-independent Markdown body display, local video playback/seek, and 20 repeated Markdown opens (including five WebView recreations) passed. Physical input, WebView keyboard focus routing, multiple DPI configurations and clean installation remain outside this validation.
