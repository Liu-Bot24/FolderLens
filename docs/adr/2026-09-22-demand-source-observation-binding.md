# 按需补全源文件观测

## 问题

目录枚举降级到不提供文件 ID 的信息类时，仍能取得有效文件条目；随后单文件句柄却可能提供完整 ID。将这两种观测直接比较，会把没有变化的文件误判为已替换。云占位符经用户同意下载后，也会发生预期的属性变化。不能通过忽略身份或放宽所有签名比较来解决。

## 决策

- 扫描仍使用批量枚举。只对实际请求读取、且扫描签名缺少身份的文件补全观测，不为整个目录逐文件打开句柄。
- 使用受控扫描工作进程核对已有大小、修改时间、创建时间及所有已知签名字段。读取前后核对文件签名、父目录身份和解析位置。
- 写入可丢弃的本地 `FileReadBindings` 缓存。有效性同时受条目版本、原扫描签名、路径版本、根代次和目录位置绑定约束；提交时再次校验这些值。并发解析不得覆盖首次接受的另一文件身份。
- 下游解码、元数据、文本索引和外部打开继续使用完整签名精确校验。失败返回真实错误，不能以新文件身份自动替代原文件。
- 云占位符默认不补全、不下载。仅在已有显式读取批准后，由受控工作进程调用 Windows Cloud Files 水合接口，保留同一文件句柄，校验身份、大小、创建和修改时间；只允许水合预期改变的属性及变更时间。不能证明一致性时拒绝绑定。
- 文本索引键加入完整源签名和新键版本，旧缓存自然失效，按需重建。

## 兼容性与资源边界

数据库主版本保持 8，增加可忽略的附属缓存表；旧应用可忽略该表。每个实际请求文件最多一条记录，受目录缓存空间预算约束。已有完整本地签名直接走原校验路径，不增加逐文件探测。

扫描工作进程协议由 5 升至 6，增加带预期签名的 `prepareRead` 请求。发布时必须配套更新主程序和扫描工作进程；混装版本应拒绝请求。准备工作有总期限，原生调用受自有工作进程和 Job 生命周期控制。

云水合可能下载整个已批准文件，但不将整个文件载入应用内存。实际云服务商兼容性尚未验证；超时、权限或不支持的提供程序不能记作成功。水合 API 依据 [Microsoft CfHydratePlaceholder 文档](https://learn.microsoft.com/en-us/windows/win32/api/cfapi/nf-cfapi-cfhydrateplaceholder)。

## 验证

真实无 ID 枚举反例、文件替换、父目录替换、根代次变化、取消、严格解码及正常 SMB 图片浏览见 [本轮验证记录](../VALIDATION_PRO_A09EB4E.md)。云批准和身份边界使用受控测试，真实云提供程序保持待验。
