# 新打开目录以本次文件枚举为准

## 问题与决定

本地根目录已移走、父目录仍可访问时，原扫描把 FileNotFound/DirectoryNotFound 转成 offline，旧 present 文件继续进入列表。旧测试也把这个场景当作离线保护。普通目录浏览不提供默认离线历史列表：新打开必须只展示本次打开代次实际观察到的文件。

- 浏览器传递不持久化的 ObservedRootEpoch；列表、快照、扩展名候选、分组统计及目录容量均限制到对应代次的 ScanRuns。未扫描到的历史文件不充当当前结果。后台元数据补充也只处理本次已发现文件。
- 手动刷新走重新打开和重新枚举，清除旧首屏，不等待旧全量扫描结束后再做第二遍。其他根已合法启动的后台扫描仍按原生命周期继续。
- 自动核对完成后重新发布文件列表，确认删除不受保持浏览顺序的保护阻挡；元数据补充本身不改变播放顺序。
- 原目录缺失、父目录可访问且卷身份已知时，枚举返回 completed/DirectoryMissing。消费端核对记录卷身份，并额外核对保存的真实位置确实消失；只有证据成立才执行缺失核对和原有收藏失效逻辑。断网、权限失败、卷不匹配或真实位置仍存在均不能据此删除记录。
- 缺失根向用户显示文件夹不存在；不可访问且本次未发现文件时显示连接/权限错误。索引仍为工作数据存储，但历史条目不再作为默认浏览内容。

## 验证与边界

原代码运行 FreshDirectoryBrowsingTests 的删除根用例失败：旧图片仍在 ReadFirstPage 中。修复后本地和隔离扫描工作进程用例通过；覆盖新打开未扫描时列表/格式/分组为空，扫描后仅有新文件，错误卷不能删除原记录。原来把本地目录移动当成离线的用例已纠正，真正父路径不可用的保护用例保留。

最终370项单元测试通过，WinUI Release编译0错误、7项NU1900。原生窗口操作未运行。未复制真实索引、未生成数据库迁移备份；此次不执行历史存储的批量清理。
