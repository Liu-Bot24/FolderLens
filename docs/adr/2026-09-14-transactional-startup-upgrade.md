# 启动升级采用事务恢复，停止自动复制整库

多次升级子步骤各自复制整个索引，导致启动长期等待和多份大文件积累。SQLite 事务能够在 SQL 失败、取消或未完成提交时保持一致性；没有必要为每一步都自动复制全库。

v4/v5 到 v7 由一个事务完成，直接按旧成员的原始文件锚点生成最终位置归属，不经过 v6 的摘要去重。v6 到 v7 保持单事务且不重写文件键。迁移同步临时设为 FULL，完成后恢复。catalog 与 sessions 分别拥有事务，不能声称跨库原子性；启动须等待两库兼容后再放行业务。

v4 改键在一个事务内按稳定 rowid 游标分批执行，保留一次索引重建，报告真实进度并检查取消。分批不等于可以恢复进度，也不能在未完成转换时允许依赖最终结构的业务。事务日志可能增长，不能用 journal_size_limit 将其描述为固定上限。

默认不再生成迁移全库副本，也不自动删除已有备份。已成功提交后的逻辑回退及运行旧版本仍需要另行保留的恢复副本；事务不替代这两种用途。此决定取代目录位置 ADR 中自动备份的策略，不改变收藏改名/移动后移除、未知状态保留的合同。
