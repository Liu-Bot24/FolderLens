# 稳定的浏览结果发布

日期：2026-09-13

## 问题

首批结果与完整快照原先使用不同的列表。快照失败重试以及首次升级都会重新绑定，取消已经显示的缩略图。原生分组适配器在空组旁移除其他组时还存在崩溃；通过整表重绑规避会重新引入闪烁。

## 决定

- 首批结果拥有稳定的虚拟列表。相同筛选重试复用它；升级按 EntryId、版本、相对路径、类型和大小保留文件行，不按序号冒认同一个文件。首批阶段支持前后切图和选择，升级保留选择。
- 自动查询合并到当前候选及最多一个待处理更新，调用方等待实际完成。明确的目录或筛选变化仍可取消旧查询。
- 分组视图直接实现 WinUI 的 `ICollectionView` / `ICollectionViewGroup`，避免默认分组适配器的第二套缓存。每次通知都保持组大小、展平数量和索引一致；小范围结构更新保留其他组及其可见容器。
- WinRT 向量没有批量插入事件。超过 4,096 项的结构更新一次替换虚拟索引，发送标准 Reset，不逐项创建数万文件行。保持绑定对象、文件行和已解码缩略图，通过当前可见文件恢复滚动位置。此时原生控件可以重建容器；不保证大批量 Reset 的容器对象身份。
- 折叠和批量发布期间持有可见缩略图，完成同步布局及定位后释放不再使用的图片，避免缩略图在回收、重新实现容器之间被清空。
- 查询失败及取消保存在本地有界诊断文件中，包含不可读筛选摘要、请求标识、阶段、错误类型/码和数据库大小，不记录源路径或文件内容。成功重试不清除此历史。

## 验证与边界

原生用例覆盖连续失败后升级、首次选图期间升级、折叠旁增删组、组排序、两处插入之间保留可见图片，以及 40,000 项批量更新无空白帧。37,329 项屏幕外新增不提前实例化文件行；百万位置的虚拟索引替换不遍历数据。

这些是隔离夹具的结果，不代替真实大目录的验收。用户归档没有重新打开；实际归档之前发生的失败原因仍需结合保留的错误证据判断。

接口依据：[ICollectionView](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/winrt/microsoft.ui.xaml.data.icollectionview)、[微软分组适配器源码](https://github.com/microsoft/microsoft-ui-xaml/blob/main/dxaml/xcp/dxaml/lib/GroupedDataCollectionView_Partial.cpp)。具体行为以项目锁定的 SDK 和原生回归结果为准。
