# 收藏夹目录规则使用稳定的来源目录

## 问题

普通扫描按所选根保存相对路径，收藏刷新按每个文件的直接父目录重新观察属性。后者的临时目录相对路径为空，原有目录规则因此在刷新或冷启动后失效。不能靠恢复旧元数据或停止收藏刷新修补此问题。

## 决策

FilterSpec v2 的收藏规则统一以完整来源目录为上下文，即文件当前来源根与该根内相对目录的组合。规则 SQL、首批及完整结果、规则预览和目录选择使用同一计算。目录名称规则可匹配该来源目录及其父目录，完整源目录路径使用 `sourcePath`；子目录匹配和例外保留优先级不变。普通浏览的名称及相对路径规则保留原语义。

旧 v1 收藏名称规则的含义可直接保留；应用后保存为 v2。旧相对路径规则若没有来源根，不能从新建的临时收藏根推断。应用在执行前显示原根目录确认，取消时不应用也不改写原规则。确认后为规则记录 `basePath`，保持原 pattern、匹配方式、启用状态和子目录选项。命名浏览设置在成功接纳后保存转换结果；会话按正常关闭保存。旧客户端会拒绝 v2，而不是忽略路径上下文继续执行。

收藏链接仍由持久收藏库管理；本次不清空、重建或降级收藏数据库。刷新继续读取当前文件属性并使旧元数据失效。临时观察来自普通扫描或收藏刷新，不再改变目录规则的解释。

## 验证契约

同一套包含／排除／例外规则在普通索引、收藏刷新、冷启动恢复后必须得到一致的首批、快照及预览计数。目录选择须覆盖直接来源文件夹和其上层。保存／恢复保持 v2 与 basePath；无法推断的旧相对路径必须有明确确认或取消，不能静默清除。
