# 后台发布保护正在浏览的内容

用户实测反馈：单击选中的图片尚未打开，就被后续加载挤出视野。此要求修订 2026-10-12 的固定数值滚动策略；保持滚动条数值不等于保持当前内容。

隔离原生反例已经确认：单击选中首项后，真实查询发布在前面插入十万项，所选行仍在、身份未丢失，但 ordinal 从 0 变为 100000，视区数值偏移仍为 0，所选图片已不可见。旧回归允许这种状态，因此未覆盖用户的要求。

## 行为

- 新目录未被操作时仍从顶部显示，不追逐扫描早期发现的任意文件。
- 用户选择、滚动或键盘浏览后，后台发布以当前可见文件及其视区内纵向位置为依据。可见选中项优先，否则使用当前视区靠上的文件。主动滚离选中项后不跳回该项。
- 新文件仍按已提交筛选和排序进入完整结果；不通过冻结扫描、隐瞒新文件或永久锁住前 256 项维持画面。
- 绑定到视图、结果源、根代次和交互代次的位置记录覆盖延迟布局；新的手势、导航或选中意图使旧记录失效。布局边界处夹到可达到的滚动范围。
- 首批读取对应的原始查询即使由显式导航发起，在用户已开始浏览之后，其晚到的提升也按后台发布处理；正在滚动时延期发布。
- 文件行和缩略图按原身份/版本守卫复用。版本变化需要新行和新内容，只允许按相同文件身份恢复位置，不能保留过时内容冒充正确显示。
- 只保留一个正在恢复的文件锚点；退出该归属时释放其屏外缩略图，不额外读取屏外页或在 UI 线程查询数据库。

## 验证

回归直接断言所选图片仍可见且保持视区位置，而非仅检查内部选择对象。覆盖单击未打开、十万项插入/删除、首批转分组、前置新组、容量排名变化、主动滚离旧选择、详情模式及候选准备期间的新选择；同时验证新增内容确实已发布。
