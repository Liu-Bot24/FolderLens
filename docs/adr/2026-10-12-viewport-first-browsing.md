# 当前视区优先的浏览链与显式滚动意图

状态：源码已实现，静态审查通过；运行验证尚未执行。未经用户授权，不运行测试、构建、应用或 UI 自动化。

## 问题

在大目录中，缩略图与点击请求读取当前页，却与全量结果比较共用串行通道；缓存命中仍等待解码名额，显示后的元数据补全继续占用名额。分组模式跳过首批显示。新目录首批发布后自动保留文件锚点，会在后来插入前序文件时把视图带离顶部。旧结果源退役还可能取消当前点击且不重试。

本次要求依据本地 FastStone 静态研究，修复整条浏览链；关联 R010、R017、R018、R019、R028、R030。保留源文件只读、内容版本检查、结果租约、数据与控件虚拟化、进程隔离和资源预算。

## 决策与检查条件

1. 结果比较、差异细化、历史路径定位和分组读取使用单独的会话读连接。当前页与快照租约使用原会话连接；保持四个常驻读连接上限。选中项绕过缩略图页缓存并发名额，通过有界高优先级队列读一页。目录属性读取的选中项也优先于等待的后台属性读取；已执行的 SQLite 语句不被错误重用或强行切换。
2. 根据真实视区安排缩略图；视区变化取消过时等待任务，下一次解码名额按最新视区选择。已经开始解码的项目正常完成，避免每个滚轮事件杀死工作进程。等待请求总量有界。
3. 分开页/属性/缓存读取与解码名额。有效缓存不获取 decoder；缓存未命中后释放前置名额，再排解码队列。先显示生成的位图，再尝试磁盘缓存；缓存保存完成前保留 worker 资产，防止后续请求清除尚在读取的文件。
4. 图片显示后的元数据使用独立、有界、可取消的队列。详情属性请求也不借用缩略图 decoder。元数据写入继续检查文件版本/根归属，不能以丢弃校验换速度。
5. 分组模式先按相同文件筛选及组内排序给出最多 256 项可用文件，并明确显示“正在整理文件夹分组和顺序”。它不代表最终分组容量排名。正式分组完成后迁移不变文件的行身份、缓存与有效选择，不能清掉正在查看的首批图片。
6. 当前点击和缩略图取页在旧结果源退役后，若同一行仍属于新源，则转入新源继续读取；根/选择已取消时不能重试，文件已离开结果时不能悄悄显示另一项。
7. 新目录及普通启动恢复目录/筛选时，从列表开头显示；扫描增量发布不得追随早期文件跳入中间。用户开始选择/滚动/键盘浏览后，才维护其文件锚点。后退/前进与显式保存视图保留历史恢复能力；用户新操作使待完成的历史定位失效，包括它正在等待数据库的情况。
8. 图片卡片区分等待、读取中、在线待确认及失败；无内容的成功项与失败项不能因 LayoutUpdated 无限重试。纯文本摘要增加尺寸时仍可继续按需读取。关闭时取消排队、等待已拥有的工作结束并解除事件订阅。

## 权衡

分组首批可能在正式分组形成后移动，必须明确临时状态，并按用户是否已开始浏览选择“保持顶部”或“保持文件”。前台读连接不被整批比较占用，并不等于任意筛选 SQL 都具有固定耗时。性能结论需要后续经用户授权的实际验证，本轮不填写运行 PASS。

## 回归覆盖计划

- 数据库后台比较被暂停时，当前页仍可读取；已排队普通读取前，高优先级读取先执行；关闭能排空两类队列。
- 新旧结果源切换时，保留行的预览接续；根或选择取消时不接续。
- 已知缓存命中不借 decoder，元数据暂停不占缩略图名额。
- 分组首批可查看，正式分组保留选中行；新目录后插入前序文件保持顶部，主动浏览后才保留锚点。
- 旧会话锚点晚到不能覆盖用户的新操作；卡片取消后回到视区能重新加载。

回归代码可以准备和静态检查；执行须遵循用户后续授权。
