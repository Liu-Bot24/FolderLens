# 2026-09-24｜目录容量独立统计与浏览数据空间保护

## 背景

原目录容量窗口从临时浏览索引汇总文件大小。大目录必须等待主浏览扫描完成；运行时索引固定 2 GiB 上限会让用户正在看的目录停止扫描，并使容量永远无法得到完整结果。该上限与“导航时停止旧目录扫描”无关，不能替代视图归属与取消机制。

## 决定

- “整个文件夹”容量改为打开窗口时独立遍历文件系统的目录元数据。每目录只保留直接文件计数与字节聚合，不将容量遍历的每个文件写入浏览索引；本地盘直接枚举，网络及可移动盘继续使用隔离的 ScanWorker。
- 在遍历期间发布明确标记为不完整的累计下界；只有待访问目录全部处理且没有不可读范围才标记完成。权限失败、离线、云延迟目录与工作进程故障不能报告为零或完整。关闭窗口、切换固定筛选快照、重新统计时取消旧容量任务。
- 固定筛选结果继续使用已经保留的结果快照，避免与另一个时间点的物理遍历混合。
- 新建的临时浏览库不再设置固定 2 GiB `max_page_count`。写入前仍检查数据盘可用空间并留出保底余量；真正空间不足时明确暂停、保留已发现数据。显式小预算仍可供测试使用。
- 浏览视图导航继续由原有根任务退休机制取消旧扫描；容量统计不调用 `PreferScanDirectory` 去推动无关的浏览索引。
- 主窗口接受新的浏览根后关闭旧根的容量窗口，并通过窗口关闭取消独立容量遍历，避免已离开的范围继续占用扫描资源。

## 边界

目录的精确大小在一般文件系统上仍须枚举目录项。独立遍历省去逐文件数据库写入、媒体解码与浏览筛选，但不宣称任何目录都能瞬间得到精确值。统计期间源文件变化可使一次结果跨越多个时间点，用户可使用“刷新统计”重算。已知分配大小不等于删除后可释放空间。
