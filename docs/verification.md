本批 Windows Release 构建通过；211 项测试通过。原生隔离夹具验证了 TXT/Markdown 内容与返回上下文、失焦后蓝色选中边框、目录规则添加/停用/预览/应用及不重扫、文档分类视图选择、首批缩略图排队、默认小图尺寸与显式适应屏幕/锁定的分离。这些结果仅证明对应测试场景，不能扩大为真实大目录稳定性全部通过。

## 已执行

- Windows x64 / Release 应用构建成功。
- 87 项相关回归测试通过，0 失败、0 跳过。覆盖扫描、目录切换、导航历史、查询差分和生命周期、分组排序、分页加载、缩略图缓存、资源调度、图片交互模型、视频外部打开与播放列表。构建有 NU1900 警告：当前网络无法取得 NuGet 在线漏洞数据；不能据此声称依赖漏洞检查通过。
- 真实 WinUI 回归窗口使用独立本地测试目录，在屏幕外运行，不接管日常浏览窗口。通过生产扫描、查询、GridView 和解码工作进程验证，而不是用网页或模拟 UI 替代。
- 旧的整表重绑定路径在同一原生检查中失败：扫描刷新替换了 ItemsSource。最终版本观察 207 个渲染帧，所跟踪的一张已显示图片的缩略图消失帧数为 0，控件容器替换帧数为 0。这项逐帧观察不代表整个视口的每一张图片都被逐帧跟踪。
- 分组列表经过重复扫描、加入新组和组内追加图片后保留 ItemsSource、已有图片对象及容器；普通列表追加至 15 项后同样保留。该输入是小型、确定性的回归样本，不是十万文件性能基准。
- 原生检查同时验证目录 A（13 项）与 B（2 项）切换、返回/前进，以及祖先节点下两个子目录均可见；默认按住倍率 250%，大视图整图放大、小预览局部放大；图片排序不提供时长，升降序箭头方向不同，关键浏览按钮有提示。
- 审计后增加的原生检查通过：多处插入前后 13 张可见旧图片保留原缩略图和容器；四次增量刷新不取消正在等待解码槽的可见请求；祖先的新子目录重新展开仍存在；关闭再开启递归后显示嵌套图片；翻页不会复用上一页细节；被放弃的查询不会淘汰已显示快照；缓存写入被空间保护拒绝时仍显示已解码图片并报告警告。
- [审计修复记录](audit-2026-09-13.md)列出各个失败反例和修复范围。原生验证程序耗时 9.86 秒，进程正常退出；使用项目内独立样本，未访问私人图片目录。

第二轮审计修复及新增验证见 [第二轮审计记录](audit-second-2026-09-13.md)，包括关闭屏障、活行身份、目录分页和多页设备恢复。大小写敏感目录导航的真实环境验证未完成。

| 问题 | 当前处理 | 验证边界 |
|---|---|---|
| 扫描更新不断闪烁 | 已有增量更新机制，但真实大目录仍报告反复刷新、缩略图清空 | 未解决；小样本原生检查不足以覆盖本次故障 |
| 分组可见图片长期加载 | 需求分页与行生命周期分离，取消单个请求不破坏共享页，重新进入视口可再次加载 | 分页取消/淘汰回归通过；大目录快速滚动仍需实测 |
| 初始少量结果不再更新 | 扫描期间更新查询；扫描中的刷新不重新开始扫描 | 扫描及查询检查通过 |
| 子目录不显示、切换后旧内容残留 | 异步读取祖先的直接子目录，导航采用当前根及查询版本校验 | 原生目录与历史检查通过 |
| 无匹配结果但原因不明 | 明示生效的高级筛选，并区分扫描中、无结果和过滤状态 | 不擅自删除用户保存的筛选 |

| 切图后才开始取图 | 预取相邻适屏图和有界中心细节区域 | 不是整幅原图所有区域预解码，不保证任意位置零加载延迟 |

### 更多筛选面板（2026-09-13）

筛选按媒体类型呈现，已有跨类型条件保持可见、可清除。日期编辑保留原时钟和未修改的精确边界；无效数字、单边日期和倒置范围不会应用。新增 `--verify-refresh --verify-filter-editor` 原生回归，覆盖上述条件往返及 320/520 DIP 的布局；已通过。普通原生浏览回归已通过。离屏原生布局检查不代表物理输入或整体视觉验收。

后续定点审计发现的两项边界已修正：整数条件使用原生文本框和精确 Int64 解析，改单端不改变另一端；日期回填按目标本地时区编码。日期行提供显式清除按钮。原生回归覆盖单端修改/清空、不同大整数、溢出拒绝、模板加载后保真，以及三个独立时区日历对象的 UTC/墙钟日期一致性。时区对象验证不替代切换操作系统时区后的完整界面验收。
后续截图复核修正了宽面板被默认对话框最大宽度裁切的问题；增加所有父容器边界检查，320/520 DIP 原生检查及截图复核通过。
