# SMB 视频封面与预览交互验证

## 根因及修复

此前的 SMB 兼容修复补充了目录句柄的旧式文件 ID，但没有补全目录枚举条目的 ID。旧式卷的扫描记录中 `PhysicalIdentity` 为空，而封面生成前的实际文件探针返回旧式 ID。完整签名比较因此在解码前抛出 `FileChanged`，尽管大小、修改时间、创建时间、变更时间和属性全部一致。

目录枚举现在根据卷的身份类型选择 `FileIdBothDirectoryInfo` 或现有扩展结构，从同一目录句柄的批量记录中取得文件 ID。旧式条目与单文件探针使用相同的卷标识、64 位索引和创建时间。不增加逐文件打开、不放宽新鲜度比较，并保留扫描期间目录替换检测。API 结构依据：[Microsoft FILE_ID_BOTH_DIR_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_both_dir_info)。

## 已执行验证

- 实际 Z、T 两个 SMB 盘的视频：旧版均在封面生成前报 `FileChanged`；修复版签名一致并成功输出 PNG 封面。本地生成视频的完整卡片、时长和预览回归通过。未改写 SMB 源文件，未把网络目录整盘复制到本地。
- 新增旧式目录枚举身份回归测试，先观察到空 ID 断言失败，再验证修复后通过。相同路径、创建时间及修改时间下替换文件，仍得到不同身份。
- 完整单元测试 **570/570 PASS**；针对身份边界和媒体新鲜度的测试 **17/17 PASS**。
- 原生 WinUI 离屏验证通过：视频卡片、播放生命周期、扫描管线、扫描中目录切换。窄窗口和宽窗口均验证首次播放入口、画面暂停、上方按钮同步、移入/移出进度控件及播放器释放。检查了生成素材的预览渲染；没有进行前台键鼠操作。
- 首次播放入口使用自适应尺寸。进度控件的操作不会被当成画面播放/暂停；已开始播放的播放器在暂停时不恢复中央遮挡图标。

本机证据：`artifacts/media-shell-20260921/` 中的 `smb-red.jsonl`、`smb-green.jsonl`、`t-red.jsonl`、`t-green.jsonl`、`tests/all.trx`、`final-*`、`video-*-final`。源路径和提取封面仅保留在被忽略的本机诊断目录。
